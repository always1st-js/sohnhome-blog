어제 노트북에서 정한 일을, 오늘 집 PC의 클로드는 처음 듣는 얼굴로 듣는다. 혹은 클로드에서 이야기한 내용을 chatgpt는 모른다. AI로 이것저것 만들다 보니 AI 창이 자꾸 늘었고 창마다 기억이 따로다. 9월 중순 기준으로 나는 노트북, 집 PC, 홈서버, 폰에서 클로드 세션 여섯을 굴렸다. 10월 들어 홈서버에 팀 이름을 단 창이 몇 개 더 생겼는데, 기억을 모으는 방식은 이 글 그대로다.

기억을 안 읽고 출발한 새 세션이, 홈서버에 이미 있는 상주 비서(늘 켜져 있는 AI 비서)를 하나 더 깔자고 권한 적도 있다. 이미 있는 걸 모르니 성실하게 또 만들자고 한 거다.

그래서 기억을 git 비공개 저장소 하나에 모았다. 다섯 세션은 그 저장소를 직접 읽는다. 연결이 안 되는 웹과 폰의 claude.ai에서 나온 건 내가 옮겨 적는다. (그런데 이제 지난달 부터 클로드 쳇과 코웍이 하나로 합쳐졌으니.. 이제 이것도 없어지겠군..) 이 글에는 그 구조와 세팅값, 그리고 AI 여럿이 한 저장소에 같이 쓰다가 밟은 함정을 적는다.

![여러 AI 세션의 기억을 모으는 공유 저장소 개념도]({{ '/assets/images/builderlog17/eli5-shared-memory-brain.png' | relative_url }})

## 바이브 코딩을 오래 하면 왜 AI가 나를 자꾸 까먹을까?

AI 세션은 기본적으로 자기가 열린 기기와 창 안의 기억만 본다. 기기가 늘고 창이 늘수록 같은 설명을 되풀이하는 일도 같이 는다.

처음엔 채팅창 하나로 만들었다. 대화가 길어져 창이 버벅이면 새 창으로 옮겼는데, 그 시절 기록에 이런 줄이 남아 있다. "렉이 심해서 새 채팅방으로 이사 왔음." 이사할 때마다 앞 얘기를 처음부터 다시 했다.

지금 내 클로드는 여섯이다. 노트북과 집 PC에 클로드 코드와 클로드 코웍(데스크톱 앱에서 내 폴더를 열어 일하는 클로드)이 하나씩, 24시간 켜 둔 홈서버에 클로드 코드 하나, 그리고 웹과 폰의 claude.ai. 같은 모델이어도 어디서 도느냐에 따라 맡는 일이 다르다. 노트북은 주력, 집 PC는 교차 확인과 서버 원격, 홈서버는 상주 비서, 폰은 이동 중 조회 담당이다.

이 여섯이 기억을 각자 들고 있으면 나는 같은 브리핑을 여섯 번 돌리는 팀장이 된다. 코딩은 모르는데 회의만 늘었다.

## AI 여섯의 기억은 어디에 모아 둬야 할까?

나는 git 비공개 저장소 하나에 적는다. 무엇을 왜 정했고 어디서 실패했는지를 마크다운 파일로 쌓는다. 기기마다 그 저장소를 내려받아 두고 한 시간마다 서로 맞춘다. 우리 집에선 이걸 통합뇌라고 부른다.

2026년 5월 초에 여러 PC 사이 동기화는 git만 쓰기로 정했다. 구글 드라이브와 섞어 쓰면 충돌, 중복, 권한 문제가 생긴다는 게 그때 이유였다. 지금은 짐마다 자리가 나뉘어 있다.

✔ 구글 드라이브: 산출물과 자산 목록  
✔ git 비공개 저장소: 코드, 그리고 AI 기억  
✔ 내 PC 디스크: 작업 중인 코드와 실행 환경  

기억 저장소는 5월 말에 시작했다. 지금은 프로젝트마다 기억 폴더가 하나씩, 모두 9개가 들어 있다. 우리는 이 폴더를 섬이라고 부른다.

![하나의 git 저장소와 여섯 개의 클로드 세션 연결 구조]({{ '/assets/images/builderlog17/d1-one-repo-six-sessions.png' | relative_url }})

그림에서 웹과 폰의 claude.ai만 점선인 이유는 세 번째 글에 적었다. 내 디스크에 닿지 않아서 거기서 나온 건 내가 옮겨 적어야 남는다.

## 클로드 코드는 그 저장소를 어떻게 자기 기억처럼 읽을까?

정션을 걸면 주소는 원래 자리 그대로인데 실제 파일은 다른 곳에 있다. 2026년 9월 기준 윈도우에서 내가 쓴 순서는 아래 그림과 같다(경로는 예시).

![윈도우에서 정션(mklink /J)으로 기억 폴더를 연결하는 작업 순서]({{ '/assets/images/builderlog17/d2-junction-order.png' | relative_url }})

그림 속 명령은 이 한 줄이다. 꺾쇠 안은 내 경로로 바꾼다.

> mklink /J <원래 기억 폴더> <저장소 하위 폴더>

순서만 지키면 된다. 복사, push(저장소 서버에 올리기) 확인, 정션. 되돌릴 땐 정션만 지우고 백업에서 원래 폴더를 살리면 된다. 겁이 많아서 기기마다 되돌리기용 백업도 따로 만들어 뒀다.

코웍은 저장소 폴더를 작업 폴더로 바로 연다. 홈서버는 저장소를 받아 오고 2분마다 올리는 방식으로 연결한다. 기기별로는 앞의 구조 그림 그대로다.

## 새 세션은 무엇부터 읽게 할까?

저장소 맨 위의 CLAUDE.md 한 장이다. 새 세션이 제일 먼저 읽는 지도(진입점)로, 기기별 세션 번호표와 섬 지도, 어떤 얘기가 나오면 어느 섬을 더 열지 적은 칸이 들어 있다.

클로드 코드는 기기마다 전역 지침 파일(저장소의 것과 이름만 같은, 기기 사용자 폴더의 CLAUDE.md)에 자기 번호와 기억 위치를 적어 두어 알아서 찾아간다. 코웍 쪽엔 부팅 스킬을 만들었다. "메모리 읽어줘" 한마디면 지도와 메인 섬 목록을 읽고 짧게 부팅 보고를 한다.

![기억 저장소 진입점 CLAUDE.md의 세션 번호표와 섬 지도 구조]({{ '/assets/images/builderlog17/d3-entry-map.png' | relative_url }})

진입점 틀을 글자로도 둔다. 값은 내 기기와 폴더에 맞게 바꾼다.

> # 기억 진입점
> ## 세션 번호표
> 번호 | 기기 | 도구 | 기억 연결
> 1 | 노트북 | 코웍 | 폴더 직접 연결
> 2 | 노트북 | 코드 | 정션
> 0 | 홈서버 | 코드 | 받기 + 올리기
> ## 섬 지도
> 폴더 | 무엇 | 이 얘기 나오면 같이 읽기
> work-auto/ | 업무 자동화 | 보고서, 시트, 봇
> home/ | 스마트홈 | HA, 서버, 텔레그램

지도를 쓰면서 배운 게 둘 있다.

첫째, 손으로 적어 둔 숫자는 금방 틀어진다. 섬마다 파일 개수를 표에 적어 뒀더니 세 번 연달아 실제와 어긋났다. 결국 표에서 숫자를 지웠다. 세는 건 기계한테 맡기는 게 속 편하다.

둘째, 세션은 지도만 읽고 다 읽었다고 착각한다. 9월 17일 기준 섬 안의 문서는 145개인데, 진입점만 훑은 세션이 이미 있는 문서를 모르고 같은 주제의 문서를 하나 더 만들었다(그날 되돌렸다). 그래서 집 PC의 클로드 코드에선 세션이 열릴 때마다 문서 파일명 목록을 즉석에서 만들어 넣는다. 섬 목록을 통째로 넣으면 59KB지만 파일명만이면 5.3KB다. 파일 이름을 문장처럼 길게 지어 둔 덕에 이름만 봐도 찾아간다.

## 여러 기기의 기억은 한 시간마다 어떻게 맞출까?

윈도우 작업 스케줄러가 한 시간마다 스크립트를 실행한다. 먼저 받고(pull) 그다음 올린다(commit, push). 노트북과 집 PC에 같은 예약 작업이 있다.

9월 초 노트북의 스크립트는 일곱 줄이었다. 바뀐 게 있으면 몽땅 담아 올리는 순진한 녀석. 지금은 안전장치(가드) 셋이 들어갔다.

![한 시간마다 실행되는 동기화 스크립트와 세 가지 안전장치(가드)]({{ '/assets/images/builderlog17/sync-guards-record.png' | relative_url }})

가드 부분을 글자로 옮기면 이렇다(줄여 적음).

> git diff --cached --quiet
> if ($LASTEXITCODE -ne 0) { exit 0 }  # 준비 칸에 변경이 있으면 이번 시간은 건너뜀
> git pull --rebase --autostash
> # 합치지 못한 파일이나 남은 임시 보관이 있으면 커밋하지 않음
> # <<<<<<< 나 >>>>>>> 로 시작하는 줄이 있으면 커밋하지 않음
> git commit ; git push  # git add -A 대신 내가 만진 파일만 경로로

첫 가드가 왜 받기 앞에 있는지, 왜 git add -A 를 걷어냈는지는 아래 사고들이 설명한다.

## 여러 AI가 한 저장소에 같이 쓰면 어디서 막힐까?

세션은 여섯인데 .git 은 기기마다 하나다. 세션끼리는 서로를 모르지만 git의 올릴 준비 칸(스테이징)은 같은 기기의 세션이 전부 같이 쓴다. 사고는 대개 한 폴더를 여럿이 같이 만지는 데서 났다.

**잠금 파일 하나가 나흘을 막았다 (7월 초).** 코웍의 샌드박스(따로 격리된 실행 공간)에서 확인용으로 git status 를 실행했는데, git이 작업 중이라고 걸어 두는 잠금 파일(index.lock)을 샌드박스가 못 지우고 남겼다. 노트북 동기화는 나흘 동안 매시간 실패했다. 지금은 샌드박스에선 git log 처럼 준비 칸을 안 건드리는 읽기만 한다. 잠금 파일을 지울 땐 실행 중인 git이 없는지부터 본다.

**남의 짐이 내 커밋에 탔다 (9월 1일).** 같은 노트북에서 세션 둘이 동시에 저장소를 만졌다. 한쪽이 파일 이름 바꾸기를 준비 칸에 올려 둔 사이, 다른 쪽이 git add -A 로 커밋하면서 그것까지 쓸어 갔다. 파일은 멀쩡했고 이력만 꼬였다.

**충돌 표시가 그대로 올라갔다 (9월 13일).** 노트북 세션이 파일 끝에 문단을 써 두고 아직 준비 칸에 올리기 전에 동기화가 돌았다. 쓰던 내용을 잠깐 치워 두고(스크립트의 --autostash 가 하는 일) 받은 뒤 되돌리다가 충돌이 났는데, 스크립트는 그걸 모르고 <<<<<<< Updated upstream 줄이 박힌 파일을 커밋하고 push 했다. 기억 파일에 충돌 표시가 그대로 남았다.

**없는 동기화를 믿었다 (9월 13일).** 홈서버 세션이 기억 파일을 고쳐 놓고 서버 자동 동기화가 가져갈 거라 믿고 두 시간을 뒀다. 그때 서버엔 그런 예약 작업이 없었다(2분마다 올리는 작업은 그날 밤에 생겼다). 진입점 문서에 있다고 잘못 적혀 있었고 세션은 틀린 지도를 성실하게 믿었다. 커밋 안 한 파일이 남은 채 다른 기기에서 같은 파일이 바뀌면 다음 받기도 막힌다.

**고쳤다고 적고 한쪽만 고쳤다 (9월 11일부터 3일).** 9월 11일 준비 칸 가드를 넣고 두 기기에 똑같이 들어갔다고 적었는데, 실제로는 노트북에만 들어가 있었다. 집 PC는 3일 동안 가드 없이 돌았다. 9월 14일 스크립트 정본을 하나로 만들고 집 PC는 정본을 불러 실행만 하는 세 줄짜리 껍데기로 바꿨다. 테스트 13개도 추가했다.

정션도 만능은 아니었다. 코웍의 가상 머신 파일을 정션으로 옮겼더니 코웍이 정션 자리는 못 연다며 거절했다. 진짜 폴더만 받아 주는 자리도 있다.

![여러 세션이 한 저장소를 쓰다 마주친 동기화 에러와 충돌 기록]({{ '/assets/images/builderlog17/incident-records.png' | relative_url }})

그림 속 메시지를 글자로도 둔다. 같은 메시지를 만났다면 이걸로 검색하면 된다.

> index.lock
> <<<<<<< Updated upstream
> error: Your local changes to the following files would be overwritten by merge
> configure: path ... is a symlink or junction, refusing to open

이 사고들에서 건진 규칙은 셋이다. git add -A 대신 내가 만진 파일만 경로로 올린다. 준비 칸 가드는 받기 앞에 둔다(받은 뒤에 막으면 쓰던 파일이 이미 치워진 다음이다). 스크립트 정본은 한 벌만 두고 기기에서는 그걸 부르게 한다. 사본을 두면 집 PC처럼 언젠가 한쪽만 고쳐진다. 그렇게 말하는 우리 노트북도 아직 사본이라 정본이 바뀌면 다시 복사해야 한다.

## 클로드 코드를 다른 도구로 바꿔도 기억이 남을까?

남게 해 뒀다. 기억은 내 디스크의 마크다운 파일과 내 git 저장소에 있고 특정 AI 서비스 안에 있지 않다. 파일을 읽을 줄 아는 도구라면 어느 쪽이든 같은 기억에서 출발할 수 있게 해 둔 거다.

첫 글에 "도구에 충성하지 말고, 기억은 내 디스크에 두자"고 적었다. 그 말을 실제로 해 본 게 이 저장소다. 세 번째 글에서는 모아 두기만으로는 모자랐던 일을 적었고 이번 글은 모아 두는 방법 얘기다.

코웍 세션을 폰으로 이어 갈 때도 읽는다. 데스크톱 앱이 꺼져 있어도 GitHub 커넥터로 저장소를 연다. 쓰기는 동기화와 부딪혀서 막아 뒀다. 다만 동기화가 한 시간 간격이라 최대 59분 전 기억일 수 있다. 그래서 폰에서 낸 결론은 초안으로만 두고 책상에 앉아 다시 본다.

그렇다고 이 구조가 3년 뒤에도 정답이라곤 못 하겠다. 지금 내가 아는 가장 덜 잃는 방법일 뿐이다.

## 따라 하려면 무엇부터 할까?

AI 창이 둘 이상이고 같은 설명을 두 번 해 봤다면 아래 순서면 된다.

✔ 기억을 모아 둘 git 비공개 저장소를 하나 만든다. 기억에는 비밀값이 섞이기 쉬우니 공개로 돌리지 않는다  
✔ 프로젝트마다 기억 폴더를 저장소 하위 폴더로 옮긴다. 순서는 복사, push 확인, 정션  
✔ 저장소 맨 위에 진입점 한 장을 둔다. 기기별 번호표, 섬 지도, 무슨 얘기면 어느 섬을 열지  
✔ 한 시간마다 동기화: 준비 칸에 올려 둔 변경이 있으면 받기 전에 건너뛰기, 충돌 표시가 있으면 올리지 않기  
✔ 세션은 git add -A 를 쓰지 않고 내가 만진 파일만 올린다  
✔ 파일 개수처럼 손으로 적는 숫자는 빼고 필요할 때 기계한테 세게 한다  
✔ 연결 안 되는 창(웹, 폰)에서 나온 건 창을 닫기 전에 옮긴다
