한글 파일을 받으면 열고, PDF로 저장하고, 닫는다. 받을 때마다 하던 이 한글 PDF 변환을 지금 내 노트북에서는 아무도 하지 않는다. 바이브 코딩으로 클로드 코드와 만든 감시 프로그램이 구글 드라이브 폴더를 지켜보다가, HWP가 들어오면 바로 옆에 PDF를 만들어 둔다. 2026년 7월 18일에 폴더에 한글 파일 하나를 넣어 봤더니 75초 안에 PDF가 생겼다.

처음부터 이렇게 조용히 일하진 않았다. 한 번은 PC 초기화로 멈췄고, 한 번은 폭주해서 내가 편집하던 파워포인트를 꺼 버렸다. 이 글에는 그 두 번을 지나 자리 잡은 구조와 세팅값을 적는다. 한글 문서가 매일 오가는 공공기관이나 회사에 있다면, 코드를 모르는 비개발자인 나처럼 클로드 코드에 말로 시켜 변환 버튼 없는 폴더를 만들어 볼 만하다.

![한글 파일을 넣으면 자동으로 PDF로 변환해 주는 감시 폴더 구조]({{ '/assets/images/builderlog15/eli5-hwp-to-pdf-folder.png' | relative_url }})

## 한글 파일을 PDF로 바꾸는 일, 왜 자동으로 하고 싶었을까?

한 번 하는 건 일도 아닌데, 한글 파일이 학습시킬때 마다 변환해야되는게 3개 파일을 넘어가는 순간 한숨이 나온다. 그나마 hwpx는 괜찮지만 hwp파일은.. 정말이지..  이런 손일은 누를 버튼을 아예 없애 버리는 게 제일 편하다. 목표는 하나였다. 사람이 변환을 시키지 않아도 PDF가 생기는 것.

내 첫 MCP 서버가 바로 이 일을 하려고 생겼다. MCP 서버는 클로드에게 도구를 쥐여 주는 작은 프로그램이다. 2026년 3월 무렵 만든 1호 서버로, 그 전에 쓰던 PDF 변환 스크립트를 클로드가 부를 수 있게 키운 것이다. 코드는 클로드가 짰다.

## 클로드 코드로 만든 첫 MCP 서버는 무엇을 했을까?

6월 7일 기준으로 도구 8개, 1,396줄이다. 한글과 파워포인트를 PDF로 바꾸는 도구, 구글 드라이브 폴더를 지켜보는 도구, 구글 시트를 읽는 도구가 들어 있다. 바꾸는 파일은 HWP, HWPX, PPT, PPTX 네 가지다.

5월 20일과 21일에 폴더 감시를 붙였다. 감시하는 폴더 안에 새 한글 파일이 생기면, 한글 프로그램을 불러 PDF로 저장해 같은 폴더에 둔다. 여기까지는 좋았는데 함정이 하나 있었다. 감시는 MCP 서버가 켜질 때 같이 시작했다. 클로드를 안 켠 날은 감시도 없었다. 클로드한테 일을 시키려고 만든 걸, 결국 내가 클로드를 켜 줘야 일하는 구조였다.

헷갈리기 쉬운 게 하나 있다. 내 PC에는 한글 문서를 새로 만들고 표를 고치는 한글 제어 MCP도 있다. 그건 남이 공개한 저장소를 가져다(포크) 쓰는 것이라 이 글의 주인공이 아니다. 이 글의 변환기는 내가 클로드에게 시켜 만든 것이다.

## PC 초기화 한 번에 왜 PDF 변환이 멈췄을까?

2026년 7월 18일에 노트북을 "내 파일 유지"로 초기화했다. 파일은 다 남았는데 변환이 멈췄다. 원인은 둘이었고, 둘 다 초기화가 남겨 주지 않는 설정이었다.

첫째, 클로드 코드에 등록해 둔 MCP 서버 목록이 통째로 사라졌다. 목록은 사용자 폴더의 .claude.json 에 적히는데, 초기화가 그걸 지웠다. 다시 등록하는 건 명령 한 줄이다.

둘째, 한글을 프로그램으로 조작할 때 쓰는 보안 모듈 등록값이 사라졌다. 보안 모듈 파일(DLL)은 멀쩡히 남아 있었는데, 그 파일을 가리키는 레지스트리 값만 없어졌다. 집은 그대로인데 문패만 떨어진 격이다. 두 곳에 같은 값을 다시 넣었다. 아래 그림이 그날 복구 기록 그대로다(경로와 이름만 가림).

![PC 초기화 후 한글 보안 모듈 레지스트리 값을 다시 등록한 복구 기록]({{ '/assets/images/builderlog15/restore-record.png' | relative_url }})

다시 넣은 뒤 한글 파일을 실제로 변환해 보고 통과를 확인했다. 내 노트북에서는 초기화가 내 파일은 남기고 사용자 레지스트리(HKCU)와 .claude.json 은 지웠다. 그래서 이 두 곳을 PC 백업 대상에 넣었다.

## 클로드를 안 켜도 PDF가 생기게 하려면?

감시를 클로드 밖으로 빼면 된다. 같은 날인 7월 18일, 감시와 변환을 맡는 상주 감시 프로그램을 따로 떼어 윈도우 작업 스케줄러에 올렸다. 늘 켜 둔 채 폴더만 지켜보는 프로그램이다. MCP 서버에서는 감시 시작을 지웠다. 둘이 같은 폴더를 보면 같은 파일을 두 번 변환하다 서로 부딪히기 때문이다. 이제 MCP 서버는 문서 읽기와 조회만 한다.

![폴더 감시와 변환을 클로드 밖 작업 스케줄러로 분리한 구조]({{ '/assets/images/builderlog15/d1-watcher-out-of-claude.png' | relative_url }})

작업 스케줄러에는 이렇게 설정했다.

✔ 트리거: 로그온할 때 자동 시작
✔ 실행 시간 제한: 없음
✔ 전원: 배터리로 바뀌어도 멈추지 않음
✔ 실패하면: 5분 간격으로 3번까지 다시 시작
✔ 실행 파일: 콘솔 창이 없는 pythonw

프로그램 안에는 두 가지를 넣었다. 뮤텍스(한 번에 하나만 켜지게 하는 잠금)로 두 벌이 동시에 켜지지 않게 하고, 한 시간마다 로그에 살아 있다는 한 줄(heartbeat)을 남긴다. 마지막으로 감시 폴더에 한글 파일을 넣어 봤고, 75초 안에 PDF가 생겼다.

작업 관리자를 열면 pythonw 가 두 개 보인다. 뮤텍스를 걸어 놨는데 왜 둘인가 싶지만, 가상환경의 pythonw 는 원래 실행기와 실제로 파이썬을 실행하는 인터프리터, 두 개로 뜬다. 정상이다.

## 상주 감시 프로그램이 폭주하면 무슨 일이 생길까?

7월 31일 오후 내내 노트북이 이상했다. 7초마다 검은 cmd 창이 번쩍였고, 파워포인트가 꺼졌다 켜지기를 되풀이했고, 타이핑이 먹통이 됐다. 범인은 내 변환 프로그램이었다.

그날 파워포인트 변환이 계속 실패하고 있었다. 구글 드라이브의 긴 경로를 다루려고 경로 앞에 \\?\ 를 붙였는데, 파워포인트는 이걸 인터넷 주소로 읽고 0x800C000E 에러를 냈다. 여기에 원인 셋이 겹쳐 폭주가 됐다.

✔ 끝없는 재시도: 실패하면 PDF가 안 생기니 "PDF가 최신이면 건너뛴다"에 영영 안 걸렸다. 구글 드라이브가 파일을 건드릴 때마다 다시 줄을 섰다
✔ 이름으로 강제 종료: 실패 처리에 taskkill /f /im powerpnt.exe 가 있었다. 파워포인트 프로그램을 이름으로 통째로 죽이니, 내가 편집하던 파워포인트도 같이 꺼졌다
✔ 콘솔 창 번쩍임: pythonw 는 콘솔이 없어서 os.system 을 부를 때마다 새 cmd 창이 떴다

기계한테 "대신 해 줘"라고 시켜 놓고, 기계가 내 창까지 대신 닫아 줄 줄은 몰랐다.

![감시 프로그램 폭주를 막기 위해 적용한 세 가지 해결책]({{ '/assets/images/builderlog15/d2-runaway-three-fixes.png' | relative_url }})

고친 건 이렇다. 같은 파일이 3번 연달아 실패하면 파일이 바뀔 때까지 건너뛴다. 파워포인트는 이름 말고 PID(실행 중인 프로그램 번호)로 끈다. 변환하려고 띄운 직후 번호를 적어 두고 그 번호만 끈다. 명령은 창 없이 실행한다. 파워포인트에 넘기는 짧은 임시 폴더 경로에는 \\?\ 를 붙이지 않는다.

덤으로 하나 더. 이 환경에서 파워포인트의 ExportAsFixedFormat 은 매번 "Python instance can not be converted to a COM object"로 실패했다. 그래서 SaveAs 에 32(PDF)를 넘기는 쪽으로 간다. 그날 기록과 지금 쓰는 두 줄은 아래와 같다.

![파워포인트 변환 오류 해결 기록과 SaveAs 코드]({{ '/assets/images/builderlog15/runaway-0731-record.png' | relative_url }})

## 따라 하려면 무엇부터 할까?

한글 파일을 받을 때마다 PDF로 저장하고 있다면, 이 순서면 된다. 나는 클로드 코드에 말로 시켰다. 바이브 코딩이면 이 목록을 그대로 붙여 넣고 시작해도 된다.

✔ 회사 PC라면 레지스트리 수정과 작업 스케줄러 등록이 막혀 있을 수 있다. 전산 담당에게 먼저 물어본다
✔ 지켜볼 폴더 하나를 정한다. 처음엔 작은 폴더로 시험한다
✔ 한글 자동화 보안 모듈을 등록한다. 레지스트리 두 곳, 등록 스크립트는 따로 저장해 둔다
✔ 감시와 변환은 작업 스케줄러가 켜는 프로그램 하나에만 둔다. 클로드 쪽에서는 감시하지 않는다
✔ 실패에 상한을 둔다. 몇 번 실패하면 파일이 바뀔 때까지 건너뛰기
✔ 한글이나 파워포인트를 끌 때는 이름 말고 내가 띄운 PID로
✔ pythonw 에서는 os.system 을 쓰지 않는다
✔ PC 초기화 전에 사용자 레지스트리와 .claude.json 을 백업한다

변환이 안 되면 이 순서로 본다. 작업 스케줄러에서 작업이 실행 중인지, 클로드 코드의 claude mcp list 에 서버가 있는지, 레지스트리 두 곳에 값이 있는지. 로그의 heartbeat 에서 실패 숫자가 늘고 있는지도 본다.

변환 버튼은 사라졌다. 대신 한 시간마다 살아 있다고 적는 로그 한 줄이 생겼다.
